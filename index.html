cretopass {{ site.version }} · Rust · MIT

A tree of secrets in the terminal.

I got tired of opening a Qt window to create an account. cretopass is the tool I use instead: a password manager in the terminal, over one age-encrypted file whose path you choose.

A node is a name plus whatever fields you need — login, password, a note, a token. Search, copy a field, move on. No account, no cloud, no network calls in the binary.

$ cargo install cretopass
Read the docs or the install script · source

What it is

Three things, each of which you can check without trusting a claim on this page.

The tree

A node is a name and the fields you give it. Search the tree, copy one field, cut a branch and paste it somewhere else, add a child under a host or a project.

The node is not a password slot with a title. A password is one field among the ones you keep.

One file

You name the path: a USB stick, a directory you already back up, a synced folder. A backup is a copy of that file, and there is nothing else to restore.

If you forget the passphrase, there is no recovery. That is the whole point of not having an account.

No network

The binary contains no network code. No telemetry, no account check, no update check — cretopass update was removed on purpose.

Updating is out of process: re-run the installer, or use the package manager that installed it.

What it does not do

These are not on a roadmap. If you need them, another tool has them today.

  • No sync, no shared account. Two machines must not write the same file at once. A share bundle is a file you hand over, not a sync channel.
  • No browser autofill, no phone app. The workflow is: you are already in the terminal.
  • No independent audit. The encryption is age; the code around it is mine. Nobody else has reviewed it.
  • A forgotten passphrase is gone. There is no reset, no recovery code, and no support address that can decrypt your file.

Where it fits

For someone who is already in the terminal, and who wants the browser and the phone left out.

Install

One binary. No daemon, no service, no config to write first.

$ cargo install cretopass
$ curl -fsSL https://github.com/Dmitrytuk/cretopass/releases/latest/download/install.sh | sh
> irm https://github.com/Dmitrytuk/cretopass/releases/latest/download/install.ps1 | iex

Linux and macOS get a binary from the release; Windows gets the same thing through PowerShell. The script installs to ~/.local/bin (or %LOCALAPPDATA%\Programs\cretopass) and checks a SHA-256 from the same release. Install details.
